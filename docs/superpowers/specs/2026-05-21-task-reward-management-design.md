# 任务与奖品管理能力设计

## 背景

PRD 的 MVP 必做项包含“创建和管理任务”“创建和管理奖品”。当前系统已经具备创建、列表、孩子领取/提交、家长审核、孩子申请兑换、家长发放/拒绝，以及新家庭默认预置任务和奖品。缺口在于家长创建后无法调整内容，也无法把不再适用的任务或奖品从可见列表中移除。

本次设计只补齐 MVP 需要的轻量管理能力：家长可以编辑任务/奖品的基础信息，也可以将任务归档、将奖品下架。删除历史数据、复杂上下架审批、批量管理和排序不纳入本次范围。

## 目标

1. 家长可以修改本家庭内任务的标题、积分和周期类型。
2. 家长可以归档本家庭内任务，归档后不再出现在可领取任务列表，也不能再被领取或直接提交。
3. 家长可以修改本家庭内奖品的名称、积分成本和库存。
4. 家长可以下架本家庭内奖品，下架后不再出现在可兑换奖品列表，也不能再被申请兑换。
5. 已存在的任务记录、奖品兑换记录、积分流水不被删除，历史列表仍可关联原任务或奖品名称展示。

## 不做范围

- 不做物理删除。
- 不做恢复上架/恢复启用入口；如果后续需要，可以基于现有状态字段增加接口。
- 不做任务/奖品排序。
- 不做批量操作。
- 不改动已经完成的任务记录和兑换记录状态。

## 方案

### 后端模型

新增四个请求模型：

- `TaskUpdateRequest`：`familyId`、`taskId`、`title`、`points`、`cycleType`。
- `TaskArchiveRequest`：`familyId`、`taskId`。
- `RewardUpdateRequest`：`familyId`、`rewardId`、`name`、`pointsCost`、`stock`。
- `RewardOffShelfRequest`：`familyId`、`rewardId`。

任务和奖品已经有状态字段：

- `tasks.status = 1` 表示启用，`0` 表示归档。
- `rewards.status = 1` 表示上架，`0` 表示下架。

因此本次不新增数据库字段。

### 服务层规则

任务：

- 编辑任务前必须校验操作者是该家庭的家长角色。
- 编辑只能操作本家庭内 `ACTIVE` 状态的任务。
- 编辑复用创建时的规范化规则：标题去空格，空标题报错；积分小于等于 0 时归一为 1；周期为空时归一为 `ONCE`；非法周期报错。
- 归档只能操作本家庭内 `ACTIVE` 状态任务，并将 `status` 更新为 `TaskStatusArchived`。
- 归档后，已有 `CLAIMED` 或 `PENDING` 记录保持原状态，家长仍可在记录列表中审核或查看历史。

奖品：

- 编辑奖品前必须校验操作者是该家庭的家长角色。
- 编辑只能操作本家庭内 `ACTIVE` 状态的奖品。
- 编辑复用创建时的规范化规则：名称去空格，空名称报错；积分成本小于等于 0 时归一为 1；库存为 0 时归一为 `-1`，表示无限库存。
- 下架只能操作本家庭内 `ACTIVE` 状态奖品，并将 `status` 更新为 `RewardStatusOffShelf`。
- 下架后，已申请的兑换记录保持原状态，家长仍可发放或拒绝。拒绝时继续按现有逻辑回退积分和库存。

### API

沿用当前路由风格：

- `POST /api/task/update`
- `POST /api/task/archive`
- `POST /api/reward/update`
- `POST /api/reward/offShelf`

接口均需要 JWT。请求体使用 JSON。成功时返回更新后的任务或奖品对象。

### 小程序

本次先补 API 封装，页面只增加轻量入口：

- 首页任务卡片在家长视角增加“编辑”“归档”操作。
- 奖励页奖品卡片在家长视角增加“编辑”“下架”操作。
- 编辑先使用当前页面内的表单状态，不新增独立页面。

这样能让 MVP 闭环可用，同时避免过早引入复杂管理后台。

## 错误处理

- 缺少 `familyId`、`taskId` 或 `rewardId` 时抛出明确错误。
- 非家庭成员访问返回权限错误。
- 孩子调用管理接口返回权限错误。
- 操作已归档任务或已下架奖品时返回 not found 类错误，避免前端误以为可继续编辑。

## 测试策略

后端优先：

1. 单元测试覆盖请求规范化：标题/名称 trim、默认积分、默认周期、默认库存、非法周期。
2. 单元测试覆盖缺少 id 的错误。
3. 集成测试覆盖家长编辑任务、归档任务后列表不可见。
4. 集成测试覆盖孩子不能编辑/归档任务。
5. 集成测试覆盖家长编辑奖品、下架奖品后列表不可见。
6. 集成测试覆盖孩子不能编辑/下架奖品。

前端验证：

1. `node --check` 校验新增 API 封装语法。
2. 对改动的 Vue 文件做乱码扫描。

## 自查

- 无新增数据库表结构，符合当前状态字段设计。
- 不删除历史数据，避免影响积分流水和记录追溯。
- 操作范围聚焦 MVP 管理能力，没有引入批量、排序和恢复入口。
- 家长权限沿用 `MemberService.RequireParentRole`，保持后端风格一致。
