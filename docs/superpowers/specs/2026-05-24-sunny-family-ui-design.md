# 亲子积分小程序 UI 设计方案：晴日家庭感

## 背景

当前小程序已经具备 MVP 核心业务能力：家庭选择与创建、邀请加入家庭、任务发布与领取提交、任务审核、奖励创建与兑换、家长代孩子完成任务、家长代孩子兑换奖励、积分流水、家庭成员与虚拟孩子管理。功能链路已经成形，但页面视觉和信息层级还偏工程化，多个高频操作混在同一屏，长列表场景也缺少承载策略。

本方案将现有功能重新组织为一套统一 UI 基线，风格目标是“温暖 + 阳光”，但保持家长管理场景所需的清晰和稳定。

## 设计目标

1. 让家长打开首页时能立即知道今天有哪些待处理事项。
2. 让孩子打开首页时能立即看到积分、可做任务和待确认奖励。
3. 让任务、奖励、成员这些会增长的内容进入可扩展列表或独立页面，避免首页和奖励页无限变长。
4. 让虚拟孩子和真实孩子共存，家长代操作不再只围绕虚拟孩子设计。
5. 让 UI 气质温暖、轻快、可信，不做过度童趣化。

## 风格方向

采用“晴日家庭感”：

- 主背景：暖白到浅天空蓝，减少纯白页面的冷感。
- 主行动色：阳光橙，用于主要按钮、积分亮点和关键 CTA。
- 辅助色：清爽蓝用于导航和信息入口，嫩绿色用于完成、通过、成长反馈。
- 警示色：柔和红，仅用于驳回、下架、错误。
- 卡片：轻阴影、低圆角到中圆角，避免过度泡泡化。
- 字体层级：页面标题克制，卡片标题清楚，数字和积分可稍突出。

不采用大面积粉色、糖果色、厚重 3D 卡片，避免长期使用时显得幼稚或疲劳。

## 页面信息架构

### 1. 选择家庭

目标是进入家庭，而不是让邀请和关联占据主要空间。

- 顶部展示“选择家庭”和一句轻量说明。
- “创建家庭”始终可见，作为主要入口。
- 已有家庭用列表展示，点击进入。
- “已有邀请码？”作为低权重折叠入口。
- 不在此页展示“关联孩子”。虚拟孩子关联应在成员管理中从具体孩子发起。

### 2. 首页

首页是今日看板，按角色展示不同重点。

家长视角：

- 顶部展示家庭名称、角色、快捷切换家庭。
- 三个统计卡：待审核、待奖励、可用任务，并支持跳转到对应区域或页面。
- 待审核任务。
- 待发放奖励。
- 代孩子完成任务，放在待发放奖励之后。
- 代孩子完成任务模块不再展示“查看全部任务”按钮，只保留当前代操作所需任务。

孩子视角：

- 顶部展示当前积分和成长反馈。
- 可执行任务。
- 待确认奖励。
- 任务状态用“领取、提交、审核中、已完成”区分。

### 3. 任务页

任务页是任务工作台。

家长视角：

- 顶部展示任务总量和发布入口。
- 发布任务表单可折叠或独立卡片展示。
- 任务管理列表支持编辑、归档。
- 同名任务只做前端提醒，允许二次确认后继续。

孩子视角：

- 展示我的任务列表。
- 支持领取、提交，操作后局部更新，不刷新整页。

### 4. 奖励页

奖励页拆成“奖励商店 + 奖励管理”的混合页，但主页面不能被代操作拉长。

家长视角：

- 顶部展示待发放数量。
- 待发放申请放在前面，支持发放、驳回，局部更新。
- 新建奖励和奖励库放在管理区域。
- “代孩子兑换奖励”改为入口卡，进入独立子页面。
- 可兑换奖励和代孩子兑换奖励的位置不再在同页长列表互相抢占空间。

孩子视角：

- 展示当前积分。
- 展示可兑换奖励列表。
- 兑换后局部增加待发放记录。

### 5. 代孩子兑换奖励页

这是奖励页的独立子流程。

- 第一步选择孩子，支持真实孩子和虚拟孩子。
- 第二步展示该孩子的积分和可兑换奖励。
- 奖励多时提供轻量筛选：全部、可兑换、积分不足、已申请。
- 点击代兑换后局部更新列表状态，不返回奖励主页面。

### 6. 积分流水页

积分流水是独立列表页。

- 家长可按孩子筛选。
- 孩子只看自己的流水。
- 流水按时间倒序展示。
- 每条流水突出积分变化，辅助展示来源、成员、时间。
- 空状态给出说明，不展示空白页。

### 7. 我的页

我的页是家庭与账户中心。

- 顶部展示当前家庭和个人积分摘要。
- 积分流水作为入口卡，不直接展示完整流水列表。
- 家庭成员模块只展示成员摘要。
- 邀请成员、创建虚拟孩子不再作为两个大按钮压在成员列表上方，而是进入“成员管理”。

### 8. 家庭成员管理页

新增独立管理页，用于承载成员相关动作。

- 顶部展示家庭成员数。
- 主要动作：邀请家长、邀请孩子、创建虚拟孩子。
- 成员列表展示角色、积分、虚拟账号标识。
- 虚拟孩子卡片上提供“邀请关联”按钮。
- 一个微信用户在一个家庭内只会有一个身份。

## 组件规则

- 页面顶部统一使用暖色渐变头部，但正文保持浅色背景，避免满屏单一暖色。
- 操作按钮分三类：主按钮为阳光橙，次按钮为蓝色描边，危险按钮为柔和红。
- 列表卡片必须有稳定高度和明确右侧操作区，避免按钮文案变化造成布局跳动。
- 筛选使用横向胶囊控件，数量不超过 4 个。
- 空状态必须包含“当前状态说明 + 下一步动作”，不只显示“暂无数据”。
- 表单默认收起或弱化，避免管理表单长期占据首屏。

## 数据与交互原则

- 高频操作局部更新，不整页刷新：领取任务、提交任务、审核通过、奖励发放、奖励驳回、兑换奖励、代孩子完成任务、代孩子兑换奖励。
- 长列表进入独立页或独立区域：奖励代兑、积分流水、成员管理。
- 首页只保留今日处理所需内容，不承载完整管理列表。
- 角色差异在同一页面内通过模块显隐处理，不拆成完全不同的导航结构。

## 错误与空状态

- 加载失败展示错误卡和重试按钮，不出现白屏。
- 家庭未选择时引导回选择家庭页。
- 无家庭时仍保留创建家庭入口。
- 无孩子时，在代操作模块和成员管理页引导创建虚拟孩子或邀请孩子。
- 无任务、无奖励、无流水时展示轻量说明，并给家长显示创建入口。

## 验收标准

1. 所有当前已实现页面都有对应设计草图。
2. 首页不再展示“查看全部任务”按钮。
3. 奖励页的代孩子兑换奖励进入独立子页面。
4. 我的页家庭成员模块不再直接并列“创建虚拟孩子”和“邀请成员”两个入口卡。
5. 页面视觉统一为晴日家庭感，不能出现杂乱的蓝色默认按钮和纯工程化卡片堆叠。
6. 长列表页面具备筛选、摘要或独立承载策略。
7. 设计产物可通过本地 HTML 文件直接查看。
