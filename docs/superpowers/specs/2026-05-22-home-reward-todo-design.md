# 首页奖励待办看板设计

## 背景

PRD 中“首页待办看板”要求家长端首页展示待审核任务、待发放奖品和关键家庭动态，孩子端首页展示新发布任务、审核中任务、已获得积分和奖品已发放。当前首页已经覆盖任务待办：孩子可以领取/提交任务，家长可以审核任务；奖励待办虽然已在奖励页可处理，但首页只展示了待发放数量，没有给出待发放列表和操作入口。

本次设计补齐首页的奖励待办，不新增后端能力，复用现有奖励记录 API 和兑换操作 API。

## 目标

1. 家长首页展示 `APPLIED` 状态的奖励兑换记录。
2. 家长可以在首页直接发放或拒绝奖励。
3. 孩子首页展示 `DELIVERED` 状态的奖励记录。
4. 孩子可以在首页直接确认收到奖励。
5. 首页刷新逻辑保持一致：操作成功后重新加载首页数据和看板数字。

## 不做范围

- 不做新的通知系统。
- 不新增“关键家庭动态”流式时间线。
- 不改变奖励页已有流程。
- 不改动后端接口和数据库结构。

## 数据流

### 家长视角

首页加载时，除了当前已有的家庭摘要、任务列表、成员列表、任务记录，还额外调用：

- `listRewardRecords({ familyId, status: 'APPLIED' })`

页面展示每条待发放记录：

- 孩子昵称。
- 奖励名称。
- 消耗积分。
- 申请时间。
- “拒绝”和“发放”操作。

点击“发放”调用 `deliverReward({ recordId })`；点击“拒绝”调用 `rejectReward({ recordId })`。成功后提示并刷新首页。

### 孩子视角

首页加载时，除了当前已有的家庭摘要、任务列表、孩子任务记录，还额外调用：

- `listRewardRecords({ familyId, status: 'DELIVERED' })`

页面展示每条待确认奖励：

- 奖励名称。
- 消耗积分。
- 发放时间。
- “确认收到”操作。

点击“确认收到”调用 `receiveReward({ recordId })`。成功后提示并刷新首页。

## UI 设计

首页继续保持当前卡片式工作台风格：

- 孩子端在任务列表上方增加“待确认奖励”区块；没有数据时不展示该区块，避免首页噪音。
- 家长端在“待办事项”中保留任务审核列表，并新增“待发放奖励”区块。
- 操作按钮沿用现有首页审核按钮风格：拒绝使用描边按钮，发放/确认使用主按钮。

## 错误处理

- 接口报错继续交给现有 request 层和页面异常流程。
- 操作成功后统一重新加载首页，避免本地状态和后端状态不一致。
- 如果记录已被其他家长处理，后端会返回状态变更错误，前端不做额外兜底。

## 测试策略

1. 小程序 API 已有奖励封装，本次只在首页引用并调用。
2. 使用 `node --check` 校验 API JS 文件语法。
3. 对首页 Vue 文件做乱码扫描。
4. 后端未改动，仍跑 `go test ./... -count=1` 作为回归验证。

## 自查

- 覆盖 PRD 首页待办中“待发放奖品”和“奖品已发放”的首页入口。
- 不新增后端复杂度，复用已验证的奖励记录和操作接口。
- 不影响奖励页，首页只是补充更高频的待办处理入口。
