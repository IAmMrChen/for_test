# 小程序个人页成员与积分流水接入设计

## 背景

后端已经提供家庭成员列表和积分流水查询接口。小程序个人页当前只展示当前家庭和三个菜单项，其中“家庭成员”“积分流水”仍是占位 toast。随着首页、任务页语义和奖励页真实数据接入完成，个人页继续停留在占位状态会影响 MVP 闭环：用户能获得和消耗积分，却不能回看积分来源；家长能创建家庭和孩子，却不能在小程序端查看当前家庭成员。

本轮只接入个人页的查询展示能力，不新增成员管理写操作，不新增积分手动调整，不新增页面路由。

## 目标

1. 个人页进入时读取当前家庭，并基于当前家庭调用后端真实接口。
2. 展示当前用户在家庭内的昵称、角色、当前积分和累计积分。
3. 展示家庭成员列表，包括昵称、角色、虚拟账号标识、当前积分和累计积分。
4. 展示积分流水列表，包括成员昵称、积分变化、来源类型、来源标题和发生时间。
5. 孩子视角只展示自己可见的积分流水，家长类角色展示全家庭积分流水。
6. 保留“切换家庭”能力。
7. 无家庭、加载中、空列表、登录过期和请求失败都有清晰处理。

## 非目标

1. 不实现成员移除、改名、角色变更。
2. 不实现创建虚拟孩子和邀请微信用户的入口。
3. 不实现积分手动调整。
4. 不实现积分流水筛选、分页、导出。
5. 不新增独立成员页或积分流水页。
6. 不修改后端接口、权限规则和数据库结构。

## 推荐方案

采用“个人页内嵌两个信息区”的方案：新增 `api/member.js` 和 `api/point.js`，把 `pages/profile/index.vue` 从菜单占位页改造成真实数据页。页面顶部展示当前身份和家庭信息，下方直接展示“家庭成员”和“积分流水”两个区块。

这个方案最适合当前阶段。它能复用现有个人页入口和上一轮已经稳定的登录、家庭选择、401 重试机制，也避免新增路由后带来的导航和页面状态管理成本。

备选方案一是新增两个子页面：家庭成员页和积分流水页。这个方案更适合数据量变大之后，但当前 MVP 数据量小，跳转层级会让验证成本变高。

备选方案二是只接积分流水，不接成员列表。这个方案能补上积分可追溯性，但会继续留下“家庭成员”占位项，个人页仍然不完整。

备选方案三是接入完整成员管理。这个范围会引入写操作、权限确认和更多异常场景，不适合本轮查询型收口。

## 文件边界

- `parent-child-miniprogram/api/member.js`：新增成员接口 client，封装 `GET /api/member/list`。
- `parent-child-miniprogram/api/point.js`：新增积分流水接口 client，封装 `GET /api/point/logs`。
- `parent-child-miniprogram/pages/profile/index.vue`：改造为真实数据页，负责加载状态、当前身份展示、成员列表、积分流水和切换家庭。
- `parent-child-miniprogram/api/auth.js`：不修改，复用 `ensureDemoLogin`。
- `parent-child-miniprogram/api/dashboard.js`：不修改，复用 `getDashboardSummary`。
- `parent-child-miniprogram/utils/storage.js`：不修改，复用 `getCurrentFamily`。
- `parent-child-miniprogram/utils/request.js`：不修改，复用统一请求和错误处理。

## 接口使用

### 家庭成员列表

```http
GET /api/member/list?familyId=1
```

返回 `FamilyMember[]`：

```json
{
  "id": 10,
  "familyId": 1,
  "userId": 1001,
  "roleType": "OWNER",
  "nickname": "爸爸",
  "currentPoints": 0,
  "totalEarnedPoints": 0,
  "isVirtual": false,
  "status": "ACTIVE"
}
```

后端规则：当前用户必须是家庭有效成员；MVP 阶段家庭内有效成员对所有家庭成员可见。

### 积分流水

```http
GET /api/point/logs?familyId=1
GET /api/point/logs?familyId=1&memberId=10
```

本轮小程序只使用不带 `memberId` 的查询。

返回 `PointLogListItem[]`：

```json
{
  "id": 1,
  "familyId": 1,
  "memberId": 10,
  "nickname": "小明",
  "points": 5,
  "sourceType": "TASK",
  "sourceId": 20,
  "sourceTitle": "阅读 30 分钟",
  "createdAt": "2026-05-20T10:00:00+08:00"
}
```

后端规则：孩子不带 `memberId` 时自动限定为自己；家长类角色不带 `memberId` 时返回家庭内全部流水。

## 页面行为

### 通用加载

1. `onShow` 读取 `getCurrentFamily()`。
2. 无当前家庭时跳转到 `/pages/family-select/index`。
3. 调用 `ensureDemoLogin()`。
4. 并行加载：
   - `getDashboardSummary(familyId)`
   - `listMembers(familyId)`
   - `listPointLogs({ familyId })`
5. 遇到 401 时强制 `ensureDemoLogin(true)` 并重试一次。

### 顶部身份区

展示：

- 昵称，优先使用 summary 的 `nickname`。
- 当前家庭名。
- 当前角色中文名。
- 当前积分和累计积分。
- “切换家庭”按钮，点击后跳转 `/pages/family-select/index`。

家长类角色当前积分通常为 0，但仍展示该字段，保持模型一致。后续如需隐藏，可另起一轮改 UI。

### 家庭成员区

展示家庭内有效成员：

- 昵称。
- 角色中文名。
- 虚拟账号标识。
- 当前积分。
- 累计积分。

成员列表为空时展示“暂无家庭成员”。正常情况下至少包含当前用户，但仍保留空状态作为接口异常或数据修复期兜底。

### 积分流水区

展示积分流水：

- 正积分使用 `+N`，负积分使用 `N`。
- 来源类型中文名：
  - `TASK`：任务。
  - `REWARD`：奖励。
  - `ADJUST`：调整。
- 来源标题，缺失时展示“未命名来源”。
- 成员昵称。
- 发生时间。

孩子看到自己的流水；家长看到全家庭流水。流水为空时展示“暂无积分流水”。

## 状态与错误

1. 加载中展示页面级 loading。
2. 无当前家庭时跳转家庭选择页。
3. 成员为空和流水为空分别展示独立空状态。
4. 操作失败沿用 `request.js` 的 toast。
5. 401 自动重新登录只重试一次；重试仍失败则交给请求层处理。

## 测试策略

1. 前端语法检查：对 `config`、`utils`、`api` 下所有 JS 执行 `node --check`。
2. 页面源码扫描：检查个人页不含明显乱码片段。
3. 后端回归：执行 `go test ./... -count=1`，确保成员列表和积分流水既有测试仍通过。
4. 手工验证路径：
   - 进入个人页可以看到当前家庭和身份信息。
   - 家庭成员区展示家长、孩子和虚拟孩子。
   - 孩子账号只看到自己的积分流水。
   - 家长账号看到全家庭积分流水。
   - 点击切换家庭可以回到家庭选择页。

## 自检

1. 范围聚焦：只做个人页查询展示，不引入成员写操作和积分调整。
2. 接口一致：接口路径和字段来自当前后端代码。
3. 角色清晰：孩子和家长的数据可见性交由后端规则保证，前端只展示接口返回结果。
4. 页面完整：原来的两个占位菜单都被真实信息区替代。
