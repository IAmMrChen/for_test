# 任务入口与首页快捷处理重构设计

## 背景

当前首页同时承担家长概览、任务发布、任务管理、代孩子完成任务、待审核任务、待发放奖励等能力。MVP 阶段这样可以快速跑通闭环，但当一个家庭有多个孩子、十几个任务时，首页会变得很重。

这次调整的核心不是删除首页能力，而是重新划分职责：

1. 首页继续承担家庭概览、待办提醒和高频快捷处理。
2. 任务管理能力迁移到独立“任务”入口。
3. 代孩子完成任务保留在首页，但改成按孩子筛选的快捷区，不再平铺所有孩子和所有任务。

## 目标

1. 底部菜单新增“任务”入口。
2. 家长首页顶部三个统计项支持跳转或定位。
3. 家长首页移除完整任务管理列表和发布任务表单。
4. 家长首页保留“代孩子完成任务”快捷区，并放在“待发放奖励”之后。
5. 家长代孩子完成任务支持真实孩子和虚拟孩子。
6. 任务页承接完整任务管理能力。
7. 前端在创建或编辑任务时提示同名任务，但允许用户继续提交。

## 非目标

1. 本次不新增服务端任务名称唯一约束。
2. 本次不改任务、任务记录、积分发放的数据模型。
3. 本次不实现任务分类、搜索、分页、批量操作。
4. 本次不实现复杂的孩子任务矩阵视图。

## 页面职责

### 首页

首页是家庭工作台，重点展示当前家庭需要立刻处理的事项。

家长视角首页保留：

1. 顶部统计：待审核、待奖励、可用任务。
2. 待审核任务。
3. 待发放奖励。
4. 代孩子完成任务快捷区。

家长视角首页移除：

1. 发布任务表单。
2. 完整任务管理列表。
3. 任务编辑和归档入口。

孩子视角首页仍展示自己的任务概览和可执行任务。后续如果任务页在孩子视角足够完整，首页可以进一步只保留摘要和快捷项，但本次不做额外收缩。

### 任务页

任务页是任务相关能力的主入口。

家长视角任务页提供：

1. 发布任务。
2. 全部 active 任务列表。
3. 编辑任务。
4. 归档任务。
5. 每个任务的基础信息：标题、积分、周期。

孩子视角任务页提供：

1. 可领取任务。
2. 已领取待提交任务。
3. 审核中任务。
4. 任务积分和周期信息。

任务页后续可以继续扩展为任务搜索、分类和历史任务管理入口。

## 底部菜单

底部菜单新增“任务”：

1. 首页。
2. 任务。
3. 奖励。
4. 我的。

“任务”入口使用现有静态图标作为 MVP 占位，后续再替换成专门的任务图标。

## 首页统计跳转

顶部三个统计项需要具备可点击反馈：

1. 待审核：点击后滚动到首页待审核任务区。
2. 待奖励：点击后滚动到首页待发放奖励区。
3. 可用任务：点击后切换到底部“任务”页。

如果小程序页面内滚动定位在当前实现中成本过高，可以先使用本页状态变量让目标区块高亮一次；但优先实现页面内滚动。

## 代孩子完成任务

### 支持对象

家长类角色可以代同家庭下所有孩子完成任务，包括：

1. 真实孩子。
2. 虚拟孩子。

原因是现实中真实孩子也可能没有稳定设备使用权，家长代操作仍是合理场景。

### 首页布局

首页代孩子快捷区放在“待发放奖励”之后。

布局采用“先选孩子，再看任务”的方式：

1. 顶部展示孩子选择按钮。
2. 默认选中第一个孩子。
3. 只展示当前选中孩子的任务状态。
4. 默认展示最多 5 条可处理任务。
5. 提供“查看全部任务”入口，跳转到任务页。

这样两个孩子、二十个任务时，首页不会变成四十条任务卡片。

### 任务状态

对于当前选中孩子，每条任务展示一个状态和一个主操作：

1. 可领取：按钮为“领取”。
2. 已领取：按钮为“提交”。
3. 审核中：按钮禁用，文案为“审核中”。
4. 本周期已完成：按钮禁用，文案为“已完成”。

当前服务端只返回 active 任务和任务记录，前端先基于 `CLAIMED`、`PENDING`、`APPROVED` 记录推导状态。周期任务的精确限制仍以服务端为准。

## 家长代操作权限

服务端当前只允许家长代虚拟孩子提交任务。本次需要调整为：

1. 家长类角色可以代同家庭下任意孩子领取任务。
2. 家长类角色可以代同家庭下任意孩子提交任务。
3. 孩子仍然只能操作自己。
4. 非家庭成员不能操作。

这不是名称或 UI 层面的变化，而是业务权限变化，需要后端和测试覆盖。

## 任务名称重复提醒

任务名称重复只做前端提醒，不做服务端强校验。

规则：

1. 发布任务时，拿输入标题 trim 后和当前 active 任务标题比较。
2. 编辑任务时，排除当前编辑任务后再比较。
3. 如果发现同名任务，弹窗提示：“已存在同名任务，仍要继续吗？”
4. 用户选择“继续”则照常调用创建或更新接口。
5. 用户选择“取消”则停留在表单。

这样既能提醒用户，也不会阻止用户有意创建同名任务。

## 数据流

### 任务页加载

1. 读取当前家庭。
2. 拉取 dashboard summary。
3. 拉取 active 任务列表。
4. 如果是孩子，再拉取自己的 `CLAIMED` 和 `PENDING` 任务记录。
5. 如果是家长，展示任务管理能力。

### 首页代孩子任务

1. 首页加载家庭成员。
2. 筛选 `roleType === 'CHILD'` 的孩子，不再要求 `isVirtual === true`。
3. 拉取 `CLAIMED`、`PENDING` 和必要的已完成记录。
4. 根据选中孩子生成快捷任务列表。
5. 领取或提交时传入 `memberId`。

## 验收标准

1. 底部菜单出现“任务”入口。
2. 家长首页不再展示发布任务表单。
3. 家长首页不再展示完整任务管理列表。
4. 家长首页“代孩子完成任务”仍存在，并位于“待发放奖励”之后。
5. 家长首页代孩子列表支持真实孩子和虚拟孩子。
6. 多孩子多任务场景下，首页只展示选中孩子的有限任务列表。
7. 家长可代真实孩子领取和提交任务。
8. 任务页可以发布、编辑、归档任务。
9. 孩子可以在任务页领取和提交自己的任务。
10. 首页“可用任务”统计可以跳转到任务页。
11. 创建或编辑同名任务时，小程序弹窗提醒，但用户确认后仍能继续提交。
12. 服务端不新增任务名称唯一限制。

## 后续方向

1. 任务页增加搜索和分类。
2. 代孩子任务区支持筛选“只看可处理”。
3. 首页统计支持更精细的视觉反馈和页面内定位动画。
4. 任务图标替换为正式设计资产。
