# 积分流水独立页面设计

## 背景

当前“我的”页直接展示积分流水列表。积分流水属于高数量、可追溯、偏审计的数据，当记录变多时会把“我的”页拖成长列表，影响家庭成员管理、邀请成员、虚拟孩子绑定等核心入口的可见性。

“我的”页应负责账户、家庭和成员管理；积分流水应成为独立页面，承接查询和筛选。

## 目标

1. 从“我的”页移除完整积分流水列表。
2. 在“我的”页保留一个低复杂度的“积分流水”入口卡片。
3. 新增独立积分流水页。
4. 家长可以查看全家庭孩子积分流水，并按孩子筛选。
5. 孩子只能查看自己的积分流水。
6. 保留现有后端接口和权限规则，不新增分页接口。

## 非目标

1. 本次不改后端 `point_logs` 查询接口。
2. 本次不实现分页、无限滚动、日期筛选和流水导出。
3. 本次不新增人工调分能力。
4. 本次不把积分流水加入底部 tab。

## 页面职责

### 我的页

“我的”页保留：

1. 当前用户和当前家庭身份信息。
2. 当前积分、累计积分。
3. 家庭成员管理。
4. 邀请成员。
5. 虚拟孩子创建和绑定邀请。
6. “积分流水”入口卡片。

“我的”页不再展示完整积分流水列表。

### 积分流水页

新增普通页面 `pages/points/index`。

页面展示：

1. 标题和当前家庭名称。
2. 当前筛选对象。
3. 积分流水列表。
4. 空状态。
5. 加载态。
6. 错误态和重新加载入口。

家长视角：

1. 默认展示全家庭孩子积分流水。
2. 顶部展示孩子筛选按钮：“全部”、每个孩子昵称。
3. 选择某个孩子后，调用 `listPointLogs({ familyId, memberId })`。

孩子视角：

1. 不展示筛选按钮。
2. 调用 `listPointLogs({ familyId })`，由后端按当前孩子身份收敛权限。

## 交互规则

1. “我的”页点击“积分流水”入口，使用 `uni.navigateTo({ url: '/pages/points/index' })`。
2. 积分流水页返回后不影响“我的”页状态。
3. 切换筛选孩子时，只刷新流水列表，不刷新整个页面。
4. 加载失败时显示错误态，不抛出运行时异常导致白屏。

## 数据流

### 我的页

1. 拉取 dashboard summary。
2. 拉取家庭成员。
3. 不再拉取 `listPointLogs`。

### 积分流水页

1. 读取当前家庭。
2. 拉取 dashboard summary，确定角色。
3. 如果是家长，拉取家庭成员并筛选孩子列表。
4. 调用 `listPointLogs` 拉取流水。
5. 切换孩子筛选时重新调用 `listPointLogs`。

## 展示规则

每条流水展示：

1. 来源标题，如任务名或奖励名。
2. 来源类型：任务、奖励、调整。
3. 成员昵称。
4. 创建时间。
5. 积分变化值。

正向积分使用正色，负向积分使用警示色。

## 验收标准

1. “我的”页不再渲染完整积分流水列表。
2. “我的”页有“积分流水”入口。
3. 点击入口进入 `pages/points/index`。
4. `pages.json` 注册积分流水页，但不加入底部 tab。
5. 积分流水页可以加载当前家庭流水。
6. 家长可以按孩子筛选流水。
7. 孩子看不到孩子筛选按钮。
8. 积分流水页加载失败时展示错误态。
9. 现有积分流水后端接口不改变。

## 后续方向

1. 增加分页或按时间分页。
2. 增加日期筛选。
3. 增加来源类型筛选。
4. 增加人工调分记录和原因展示。
