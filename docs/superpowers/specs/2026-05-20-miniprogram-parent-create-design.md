# 小程序家长端发布任务与新建奖励设计

## 背景

后端已经支持家长类角色创建任务和奖励，小程序端也已经完成首页任务操作、奖励兑换、个人页成员与积分流水查询。但目前小程序仍缺少“家长发布任务”和“家长新建奖励”的入口，导致任务和奖励数据还需要依赖后端或数据库预置。对 MVP 来说，孩子领取任务、提交任务、兑换奖励的链路已经基本跑通，下一步自然是让家长能在小程序端创建这些可被孩子使用的基础数据。

本轮只接入家长端创建能力：在首页为家长提供发布任务入口，在奖励页为家长提供新建奖励入口。不实现编辑、归档、上下架、删除和复杂配置。

## 目标

1. 家长类角色可以在首页发布任务。
2. 发布任务时填写任务标题、积分和周期类型。
3. 任务发布成功后，首页任务列表自动刷新。
4. 家长类角色可以在奖励页新建奖励。
5. 新建奖励时填写奖励名称、所需积分和库存。
6. 奖励创建成功后，奖励页列表自动刷新。
7. 孩子角色不看到创建入口。
8. 表单有基础前端校验，避免空标题、空名称和非法数字直接提交。
9. 登录过期、请求失败和无当前家庭继续沿用现有处理方式。

## 非目标

1. 不实现任务编辑、归档、上下架、删除。
2. 不实现奖励编辑、上下架、删除。
3. 不实现任务适用成员、任务截止时间、任务说明、任务图片。
4. 不实现奖励图片、分类、兑换限制。
5. 不新增独立页面路由。
6. 不修改后端接口、状态机和数据库结构。

## 推荐方案

采用“页面内折叠创建表单”的方案：

- 首页家长视角的任务区域上方增加“发布任务”按钮，点击后展开一个轻量表单。
- 奖励页家长视角的奖励列表上方增加“新建奖励”按钮，点击后展开一个轻量表单。
- 表单提交成功后重置表单、收起表单并刷新当前页数据。

这个方案贴合当前页面结构，不需要新增路由，也不需要维护跨页面编辑态。创建入口和创建后的列表结果在同一屏内闭环，适合 MVP 快速验证。

备选方案一是新增独立“发布任务页”和“新建奖励页”。这个方案更适合后续复杂表单，但当前字段很少，单独页面会增加导航、返回刷新和页面注册成本。

备选方案二是先只做发布任务，不做新建奖励。这个方案能解决任务数据来源，但奖励页仍然依赖预置数据，孩子兑换链路不够自洽。

备选方案三是一次性做完整管理后台。这个方案范围过大，会引入编辑、删除、状态管理和更多权限分支，不适合当前收口节奏。

## 文件边界

- `parent-child-miniprogram/api/task.js`：新增 `createTask(data)`，封装 `POST /api/task/create`。
- `parent-child-miniprogram/api/reward.js`：新增 `createReward(data)`，封装 `POST /api/reward/create`。
- `parent-child-miniprogram/pages/index/index.vue`：家长视角增加发布任务表单和提交逻辑。
- `parent-child-miniprogram/pages/rewards/index.vue`：家长视角增加新建奖励表单和提交逻辑。

## 接口使用

### 发布任务

```http
POST /api/task/create
```

请求体：

```json
{
  "familyId": 1,
  "title": "阅读 30 分钟",
  "points": 10,
  "cycleType": "DAILY"
}
```

`cycleType` 可选值：

- `ONCE`：一次性。
- `DAILY`：每日。
- `WEEKLY`：每周。

前端表单默认值：

- `title`：空字符串。
- `points`：10。
- `cycleType`：`DAILY`。

前端校验：

- 标题去除首尾空格后不能为空。
- 积分必须是大于 0 的整数。
- 周期类型只能来自三个固定选项。

### 新建奖励

```http
POST /api/reward/create
```

请求体：

```json
{
  "familyId": 1,
  "name": "周末看电影",
  "pointsCost": 30,
  "stock": 0
}
```

库存约定：

- 小程序表单里 `stock = 0` 表示不限库存。
- 后端会把 `stock = 0` 规范化为 `-1`。
- `stock > 0` 表示有限库存。

前端表单默认值：

- `name`：空字符串。
- `pointsCost`：30。
- `stock`：0。

前端校验：

- 奖励名称去除首尾空格后不能为空。
- 所需积分必须是大于 0 的整数。
- 库存必须是大于等于 0 的整数。

## 页面行为

### 首页发布任务

只对家长类角色显示发布入口，家长类角色为：

- `OWNER`
- `ADMIN`
- `PARENT`

入口位置：

- 首页家长视角内容区，在统计卡片之后、任务列表或待办事项之前。

交互：

1. 默认只显示“发布任务”按钮。
2. 点击按钮展开表单。
3. 表单包含标题、积分、周期类型。
4. 周期类型使用三个按钮切换：一次性、每日、每周。
5. 点击“取消”收起表单并重置。
6. 点击“发布”校验通过后调用 `createTask`。
7. 成功后 toast “任务已发布”，刷新首页数据。

本轮不新增任务说明字段，不对孩子指定适用范围。创建后的任务进入现有任务列表，孩子可按已有领取流程处理。

### 奖励页新建奖励

只对家长类角色显示新建入口。

入口位置：

- 奖励页家长视角内容区，在待发放申请之后、可兑换奖励列表之前。

交互：

1. 默认只显示“新建奖励”按钮。
2. 点击按钮展开表单。
3. 表单包含奖励名称、所需积分、库存。
4. 库存填 `0` 表示不限库存。
5. 点击“取消”收起表单并重置。
6. 点击“创建”校验通过后调用 `createReward`。
7. 成功后 toast “奖励已创建”，刷新奖励页数据。

孩子角色继续只看兑换列表和待确认收到记录，不看到新建入口。

## 状态与错误

1. 提交中禁用当前表单的提交按钮，避免重复提交。
2. 表单校验失败使用 `uni.showToast({ icon: 'none' })` 给出明确提示。
3. 请求失败沿用 `request.js` 的统一错误 toast。
4. 401 重试沿用页面现有 `ensureDemoLogin(true)` 机制。
5. 创建成功后重置表单，避免下次打开残留旧值。

## 测试策略

1. 前端语法检查：对 `config`、`utils`、`api` 下所有 JS 执行 `node --check`。
2. 页面源码扫描：检查首页和奖励页不含明显乱码片段。
3. 后端回归：执行 `go test ./... -count=1`，确保任务和奖励既有流程仍通过。
4. 手工验证路径：
   - 家长进入首页可以展开发布任务表单。
   - 标题为空时发布失败并提示。
   - 发布任务成功后列表刷新，孩子可看到新任务。
   - 家长进入奖励页可以展开新建奖励表单。
   - 奖励名称为空时创建失败并提示。
   - 新建奖励成功后列表刷新，孩子可看到新奖励。
   - 孩子角色不显示发布任务和新建奖励入口。

## 后续扩展

1. 独立任务管理页，支持编辑、归档和筛选。
2. 独立奖励管理页，支持编辑、上下架和库存调整。
3. 任务说明、截止时间、指定孩子。
4. 奖励图片、分类和兑换条件。
5. 创建虚拟孩子和邀请微信用户入口。

## 自检

1. 范围聚焦：只接入创建任务和创建奖励，不扩展完整管理后台。
2. 接口一致：接口路径、字段和枚举来自当前后端代码。
3. 角色清晰：只有家长类角色看到创建入口，孩子不看到。
4. 页面闭环：创建成功后刷新当前页面列表，用户能立即看到结果。
